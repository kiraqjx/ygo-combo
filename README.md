# 决斗推演室 · YGO combo

纯前端的游戏王工具集：卡牌检索、起手算率、真实对局与 AI 代打（OCG 内核）、录像手坑复盘与 AI Skill 包。
技术栈：Vue 3 + TypeScript + Vite + Pinia + Vue Router + ocgcore-wasm，无后端。

## 功能

### 1. 卡牌检索

- 全卡池中文索引（约 14,300 张），本地检索、无需逐次请求。
- 支持按 **卡名 / 日文名 / 英文名 / 效果文本** 联合检索，多关键词空格分隔。
- 结构化筛选：卡片种类（怪兽 / 魔法 / 陷阱）、子类型（通常 / 效果 / 融合 / 同调 / 超量 / 连接 / 灵摆 / 调整 / 速攻 / 永续 / 反击…）、种族、属性、等级·阶级·连接、攻击力 / 守备力区间、灵摆刻度区间。
- 排序、无限加载、卡片详情抽屉（中文效果、日文名、英文名、卡号、连接标记）。

### 2. combo 路线（录像录入）

- combo 不再手工编排：打一局（或导入 `.yrp`）后「绑定到卡组」，录像就是这条构筑的路线样本。
- 每份录像解析成起手、逐步操作、连锁与手坑命中点；启动点按**录像起手**自动关联（起手包含启动条件的全部卡才算命中）。详见「AI Skill 包」。
- 录像字节与解析结果存 IndexedDB，删除卡组不会连带清掉录像。

### 3. 起手与启动率

按主卡组构成计算起手概率：单卡至少一张上手、指定多卡同时上手（超几何分布），支持把「启动点」定义成多卡组合并批量统计（`lib/rates.ts` / `lib/starter.ts` / `lib/odds.ts`，重计算跑在 Web Worker 里）。

### 4. 真实对局（OCG 内核）

- 用 `ocgcore-wasm` 跑真实规则：可以自己操作，也可以让对手当沙包自动响应。
- 支持导入 `.yrp` 录像回放、暂存 / 恢复到任意步骤（内核确定性：同种子 + 同响应序列 → 同状态）。
- 打完可以「绑定到卡组」，成为下面的录像分析样本。
- 卡组可以一键导出成竖版长图（卡图走同源代理，画进 canvas 导出）。

### 5. 录像手坑分析

对绑定到卡组的 `.yrp` 逐份重放内核，从结构化事件流反推「假设对手手上正好有这些卡，能在第几步打断」。目前覆盖 7 张：**灰流丽、灵王的波动、无限泡影、屋敷童、幽鬼兔、锁鸟、原始生命态 尼比鲁**（抽卡型手坑如增殖的G、欢聚友伴系列故意不体现）。

判定要点：

- 召唤是否成功以内核的 `SUMMONED` / `SPSUMMONED` 为准，被神字辈无效的召唤不计入陨石次数。
- 灰流丽看「卡组 → 手卡 / 墓地 / 怪兽区」的实际移动；从卡组解放 / 当素材送墓不算。
- 屋敷童按结算结果判（墓地的卡被回收 / 回卡组 / 特召 / 除外），墓地发动的效果去卡组找牌是灰流丽的活。
- 灵王的波动按「效果里是否含特召」整次无效，命中点记在发动那一步。
- 幽鬼兔只能炸已经表侧表示在场的卡，卡片自身刚发动那一下炸不了。
- 锁鸟只在主要阶段、只由检索触发。
- **自排连锁**：同一时点自己排成 C1..Cn 时，对手只能响应最后一条，前面几条会被标成「已规避」——保留这些点是为了说明自排连锁的意义。
- 只展示前 20 步的命中点。
- 解析结果按规则版本号缓存在 IndexedDB，规则改动后会自动标为「手坑分析已过期」并提示重新解析。

### 6. AI Skill 包

把卡组、启动率配置、手坑定义与**绑定的 .yrp 录像**拼成一套 Markdown（`00-router.md` + 分片文件）或全量文档，方便直接喂给 AI 学习这套展开与应对。

combo 通过录像录入：每份可解析的录像按**起手**挂到对应的启动点（单卡动点要求起手有那张卡，两卡 combo 要求两张同时在起手），生成 `20-replay-*.md`；启动点路由表里的 `file` 字段就指向这份路线文件。

### 7. AI 代打

对局页可以开「AI 代打」，让模型接管我方操作。策略是**先规划、再执行、被打断才重规划**：

- **起手规划**：第一次轮到我方操作时，把起手、卡组构成与 skill 索引交给模型，产出一条路线（终场目标、执行顺序、要避免的坑、手坑应对）。模型可以用 `read_skill` 工具按需拉取具体分片，不必一次塞进全文。
- **沿路线执行**：路线在手就**全部本地执行**，一步一问模型的情况不会出现——候选能按路线里的卡名 + 动作对上就照路线走，对不上退确定性策略（连锁放弃响应、主要阶段收尾、取牌按 墓地 > 卡组 > 手卡 > 场上 顺序）。解放 / 弃手卡 / 格位这些岔路也走本地裁定。
- **打断重规划**：事件流里出现对手连锁或我方效果被无效时标记打断，下一次主要阶段操作前带着「发生了什么」重新规划；路线连续 3 步对不上局面同样视为偏离。**只有「还没有路线」或「刚被打断」才走单步决策**（`decide()` 的 json 小 prompt）。

单步决策时候选统一编号再交给模型，回应只需给编号，编号 → 内核响应是确定性映射。两种回答形态：

- **单选**：主要阶段操作、连锁响应、是/否、效果分支、表示形式，`action` 给一个数字。
- **多选**：检索选卡、解放、凑数值，`action` 给编号数组，数量必须落在内核的 min–max 内。候选卡片会带区域、卡名与效果摘要，检索时模型据此判断该拿哪张。可选项正好等于必须选的数量时直接作答，不问模型。

格位放置与排列顺序仍走确定性策略（候选多、选错会被内核判非法，且对结果影响很小）。

模型输出不是合法 JSON、空白内容或编号越界都会重试一次，仍失败则退回最保守的合法动作（单选：放弃响应 > 结束回合；多选：按固定顺序取满足条件的前几张），保证内核不会卡死。

模型接入走 OpenAI 兼容协议（默认 `deepseek-flash`），配置存在 localStorage，不进对局记录。浏览器直连 `api.deepseek.com` 没有 CORS 头，因此默认请求本站的 `/api/llm` 反代（dev 由 Vite 转发，生产需在反向代理上加同样的 location）。

## 本地运行

```bash
npm install
npm run dev        # http://localhost:5173
npm run typecheck  # vue-tsc --noEmit
npm run build      # 产物输出到 dist/
npm run preview
```

对局内核需要的 Lua 脚本与卡名描述已经在 `duel-assets/` 里；内核升级导致脚本对不上时可以重新拉取：

```bash
npm run assets:duel
```

纯静态站点。若部署到 Nginx 等服务器，请为 History 路由配置回退到 `index.html`：

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

要用「AI 代打」还需要把模型请求反代成同源（否则浏览器会被 CORS 挡掉）：

```nginx
location /api/llm/ {
  proxy_pass https://api.deepseek.com/;
  proxy_set_header Host api.deepseek.com;
  proxy_read_timeout 120s;
}
```

不想在站点侧转发的话，也可以在 AI 设置里把接口地址填成自己的网关，模型请求完全由浏览器直连。

## 数据来源

- 卡牌数据：`https://ygocdb.com/api/v0/cards.zip`（中文卡库，约 2.4MB 压缩包）。首次打开时下载、解压并归一化，随后缓存到 IndexedDB，之后离线可用。
- 卡图：`https://cdn.233.momobako.com/ygopro/pics/{id}.jpg`，失败时回退 YGOPRODeck 图源。
- 卡库不可用时会自动退回 ygocdb 在线检索接口。
- 对局脚本 / 描述：`duel-assets/`（`npm run assets:duel` 从 ocgcore 官方脚本与 ygopro 数据库拉取）。
- 正式服没收录的新卡 / 先行卡可以手动录入（只写卡名、种类、卡号与效果文本），与下载卡库合并使用。

## 说明与局限

- 工坊里的推演是**基于事件标记的近似模型**，用于复盘与教学，不替代官方裁定。复杂连锁（多效果同一时点、效果外文本、特殊裁定）需要手动修正事件标记。
- 录像分析是**潜在命中点**：录像里没有对手手牌，只表示「对手手上正好有这张卡」时的打断位置；自排连锁、成本 / 解放等特例已经在规则里处理，但仍是近似。
- 抽牌数按「手坑落地后仍成功执行的步骤」统计；如果某步被无效，则该步的召唤不计入抽牌。
- 陨石判定以「累计召唤次数」为阈值（只统计我方召唤），并按场上怪兽依赖判断清场后的可续性。
